# OpenSpec lifecycle

This repository uses the native OpenSpec `spec-driven` schema and the native OpenSpec change lifecycle. The SDD Framework does not fork a custom schema in this foundation and does not redefine OpenSpec command semantics.

Authoritative command behavior lives in the vendor-managed Cursor assets (`opsx-*` commands and `openspec-*` skills). This page describes the installed surface and a typical orientation of work; it does not replace those files. How participants collaborate through a change — stages, gates, review, and durable versus session information — is defined in [workflow system](../architecture/workflow-system.md). This page does not own that collaboration model.

## Change flow

```
explore → propose → apply → sync → archive
```

This is a typical orientation, not a mandatory OpenSpec execution sequence. Prompts initiate lifecycle work; they are not specifications. How humans write those prompts is defined in [human-AI interaction](../practices/human-ai-interaction.md).

| Stage | Purpose |
|---|---|
| **Explore** | Clarify ideas, problems, requirements, and constraints. Command behavior is defined by OpenSpec. |
| **Propose** | Create the change and generate proposal, specs, design, and tasks. |
| **Apply** | Implement the approved tasks. |
| **Sync** | Merge delta specs into main specs without archiving. |
| **Archive** | Finalize a completed change; sync specs if needed, then move the change to archive. |

Framework changes are specified and tracked in this repository's OpenSpec workspace. Implementation of a framework change does not bypass the proposal, specification, and task artifacts required by the schema.

## Installed Cursor surface

These assets are generated by OpenSpec and are vendor-managed:

| Command | Skill | Use |
|---|---|---|
| `/opsx-explore` | `openspec-explore` | Discovery and clarification. |
| `/opsx-propose` | `openspec-propose` | Create a change and its planning artifacts |
| `/opsx-apply` | `openspec-apply-change` | Implement tasks |
| `/opsx-update` | `openspec-update-change` | Revise existing planning artifacts |
| `/opsx-sync` | `openspec-sync-specs` | Merge deltas into main specs |
| `/opsx-archive` | `openspec-archive-change` | Archive a completed change |

Vendor files stay under `.cursor/commands/opsx-*` and `.cursor/skills/openspec-*`. Do not rename them or treat them as SDD Framework-owned. Future framework-owned Cursor assets use the `sdd-*` namespace; see [architecture overview](../architecture/overview.md).

`/opsx-update` may mention other OpenSpec commands that are not installed in this repository's core profile. Use the table above as the installed surface.

## Specification universes

- This repository: framework requirements only (`openspec/specs/` after archive).
- Consuming projects: product requirements in their own OpenSpec workspaces.

Do not add product features to this repository's specifications. How other repositories consume the framework is defined in [adoption](../architecture/adoption.md).
